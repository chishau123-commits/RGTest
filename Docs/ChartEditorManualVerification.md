# 独立制谱器人工核验

对象：Windows x64 便携 EXE，`ChartEditor/` 独立源码；Android/iPad 浏览器采集端。审核人请记录构建 SHA-256、Windows/浏览器版本、平板型号与日期。下面的“预期”是验收标准，不代表全部已人工执行。

| 项目 | 操作 | 预期与证据 |
|---|---|---|
| 独立运行 | 在无 Unity 环境复制并运行便携 EXE | 自动打开 38 音符原创演示；播放有声音；无需安装 Unity/Node |
| 空白制谱 | 新建，导入音乐，设置 BPM 与偏移，在舞台放两类音符 | 属性可编辑；缩圈边缘和移动圆在判定时重合；工程保存、重开后数据一致 |
| 路径联动 | 拖动到位音符接收圆，再拖动黄色路径起点 | 终点与接收圆一致；起点不被误当作接收目标；一次拖动一次撤销 |
| 时间拖动 | 在音符轨拖动音符；在相机轨拖动相机 | 拍线吸附；音符预读长度保持；相机重叠被报告 |
| 变速 | 设置第二段 BPM、定位跨段，修改 BPM、撤销 | 音符 tick 不变，秒数按各段积分；撤销恢复原秒数 |
| 命令历史 | 新增、复制、删除、修改半径/BPM，连续撤销重做 | ID 不冲突；曲线/路径与音符一致；新编辑清空 redo |
| 相机预览 | 添加平移/旋转/缩放，跳到起点、中点、终点，反复定位 | 同一时间总得到相同画面；绝对相机动作正确插值；HUD 不随舞台运动 |
| A/B 循环 | 设置有效 A<B，播放经过 B，保存工程后重开 | 返回 A；范围和启用状态恢复；录制期间不能启用循环 |
| 非法导入 | 打开重复键、未知动作、非法半径、缺引用 JSON | 显示原因；当前工程保留；不静默丢字段 |
| 导出 | 用演示音频导出 JSON，通过已有 Android PushChart/重启流程导入 | 手机两种音符与相机时间和制谱器一致；记录导出文本 hash |
| 正常关闭 | 修改后关闭程序，不手动保存，再启动点恢复草稿 | 正常退出前恢复草稿保存成功；可以找回修改 |
| 配对 | 开启连接、同网平板扫码/输入完整地址 | 显示已连接与同步；端口/令牌有效；关闭连接后不能继续录入 |
| 两秒倒数 | 从指定补录位置开始录制，在倒数中也点画布 | 有清晰倒数；音频起点前的触控不进入有效音符样本 |
| 多点 Began | 同时 2、3、5 指及设备更高能力落指 | 各落指分别保存；持指/滑动/抬指不增加样本；记录实际观察数量 |
| 时钟与网络 | 连续录入 1–5 分钟；在无线拥塞时测试 | 原始样本时间来自平板单调钟；RTT/不确定度可检查；不使用到包时刻作节奏时间 |
| 强运镜 | 在快速旋转/平移/缩放时点击看到的目标 | 原始 Take 保留 displayed pose、frame version、时钟模型；反投影位置对应所见历史画面 |
| 停止和迟到 | 停止时仍有在途样本，再开始新 Take | 符合旧有效区间的迟到包只回填旧 Take；停止之后的样本不混进新轮 |
| 断线/后台 | 录入时断网、浏览器后台，再恢复 | 本轮结束，已落盘触点可恢复；需要新 Take；不会跨代消费 |
| 量化与校准 | 录制双押，在自由 tick 和拍线网格分别导入；尝试 ±校准 | 原始 Take 不变；量化才合并到同 tick；整批导入可撤销 |
| 崩溃恢复 | 使用可丢弃测试工程，在录制中结束测试进程 | 已 ACK 的 journal 前缀可恢复；未结束 Take 标记 interrupted，不冒称正常停止 |
| 长路径/中文 | 用中文目录和文件名保存、覆盖、重新打开 | 完整内容写入；不出现临时残片或截断文件 |
| iPad | Safari 横屏配对、触控录入、回到前台 | 核验 PointerEvent 时间、实际多指、全屏可用性；设备未提供前保持未验收 |

## 导入现有 Android 游戏

使用演示节拍音频的谱面导出为 `prototype-chart.json`，再从仓库根目录执行已有流程：

```powershell
./tools/android.ps1 -Task PushChart -ChartPath '完整的谱面JSON路径'
./tools/android.ps1 -Task Launch
```

如游戏正在运行，先在游戏里重开以重新载入覆写谱面；ADB 启动已有进程未必触发重新载入。检查手机标题、两种运动、同拍数量和运镜段。自动演奏只是结构测试，真实落指需另验收。

## 录入精度记录

听电脑实际输出，比较本地参考与远端样本，记录样本数、早晚误差分布、RTT、同步不确定度、导入校准、平板显示延迟估计和音频输出估计方式。用不同 BPM、不同刷新率与至少一分钟连续片段交叉检查。不要把 UI 显示的“±不确定度”当成真实输入精度结果。
