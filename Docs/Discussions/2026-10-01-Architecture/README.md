## 1. 已确认的需求（2026-10-02）

1. **主体是音乐游戏。** 社区、开放创作是远期，不在当前范围。
2. **关键在三件事：内容生产管线、交换协议、具体内容质量。** 质量后续逐步迭代；当前只保证它**能**迭代，不比较质量好坏。
3. **方法：从需求入手，设计与实现只要满足需求；贯彻第一性原理。**
4. **协议是通用实现。** 内容生产层如果能直接产出协议内容，最好；否则经转换脚本或 agent。它不取代 bgv-chartgen 存档分支里的 ADR-0001（成品是实时渲染的程序）。
5. **bgv-chartgen 是内容生产 agent 的最终实现**，形态是适配各 agent 框架的一套 skill，不绑定某个 agent 或 CLI 工具。
6. **协议是一套逻辑 schema，从零开始设计。** 现有谱面定义有缺陷，不以它为锚。协议单独成仓库：`LingXuanYin/rg-protocol`。
7. **需求贯穿三个仓库**：RGTest、bgv-chartgen、rg-protocol。三者的改动与文档统一管理；管线及其文档放 bgv-chartgen。
8. **分支：协议先支持好；太复杂就先只留接口。** 具体玩法（高级玩法设计）先不考虑。

同一天第一轮 grill 的答复：

9. **本轮的成功标准是端到端的最小闭环**：音频 → chartgen skill → 协议内容 → 校验 → 在制谱器里改一个元素 → 游玩 → 改动与反馈回到 agent。
10. **一首歌一份内容，各难度是其中的并列变体。**
11. **所有组件之间交换内容都走这一份协议**（agent、转换、制谱器、游玩器、社区），不留旁路。协议要求无损往返、保留不认识的扩展、元素有稳定 id。
12. **谱面与展示在原型里已经耦合**，协议要同时容纳两者，甚至会装代码：定义必须非常自由，但必须有该有的接口和规范；宁可以后再加限制。先前「按判定把游戏事件与内容事件切开」的读法作废。
13. **主要的生产者是 agent**；人必须能在制谱器里改，并通过 agent 反馈改动。
14. **旧谱面、旧协议一律不兼容，完全从头来。** 为了验收可以扩展开发边界，例如建参考宿主、测试件。
15. **原型指 bgv-chartgen 存档分支里的「成品」**：实时渲染的程序（参考骨架在浏览器端，可测接口 `chartgen-test/1` 走 WebSocket）。它的谱面描述 `chartgen-chart/1` 是与媒介无关的游戏事件数据，动作由成品自己定义、没有枚举。出处：存档分支 `archive/2026-10-01` 的 `docs/adr/0001-0003`、`docs/chart-description.md`、`docs/test-interface.md`。

## 4. 待 grill（未确认，不是决定）

### 内容的边界

- **难度在一份内容里怎么表示**：每个元素带一个难度维度，还是每个难度一套游戏事件、共用同一份展示？这条不定，模板、能力声明、无损往返的判断都要重审。
- **媒体算不算内容的一部分**：算，则无损往返要覆盖媒体字节；不算，则媒体怎么寻址。
- **素材的授权与溯源要不要进协议**：成品要对外发布，以后再补是破坏性改动。

### 时间与分支

- **段落之间怎么连。** 白板的「创建『创建分支』的规则，而不是创建分支」允许各臂不等长；本仓库 `CONTEXT.md` 的**汇流**要求所有臂在同一个 tick 回到主线、不累积历史。两者是不同的拓扑，Q25 的时间模型按前者定。
  **已裁定（2026-10-04）**：段落图是 DAG、各臂可以不等长，等长由内容自己声明——rg-protocol 的 [ADR-0008](https://github.com/LingXuanYin/rg-protocol/blob/main/docs/adr/0008-segment-graph-allows-unequal-arms.md)。本仓库的**汇流**是等长的一个特例，没有被推翻；`Docs/VideoBgaBranchingPlan.md` 因此**不被取代**，它描述的等长汇流属于这一特例。图的分叉条件怎么写仍未定。
- **时间单位**：rg-protocol 的 v0 草案按秒计；要不要改用拍，拍网格（tempo map）要不要进协议。

### 展示与宿主

- **Q18 三维玩法与相机**：要么相机（连同投影）进核心、且只许时间驱动；要么三维部分的判定由内容生产侧烘焙成屏幕空间轨迹。讨论时约定等重写之后再议。
- **展示的原语清单**：展示元素有哪几种、三种驱动的具体形状、求值顺序与合并方式。
- **中端 Android 的成本预算**：同屏多少元素、几路序列帧，需要实测。给不出这些数，Q22 的「放给生产侧选」就是盲选。
- **能力声明由谁检查、什么时候拒绝、拒绝了怎么办**：游玩时拒载？制谱器拒存？整份拒绝还是降级？

### 管线与仓库

- **质量迭代还要记什么**：来源标记与改动清单已定（Q14），生成来源、人的反馈原文要不要记，记在协议里还是管线里。
- **现有谱面定义的缺陷清单**（从零设计的输入）。已知的有：一半集合按下标寻址；`JsonUtility` 丢掉不认识的字段；拍与时长用单精度；`SceneObjectData.sourcePath` 存本机绝对路径。
- **rg-protocol 怎么被 RGTest 与 bgv-chartgen 引用**：本仓库要求单独克隆即可打开，私有子模块会让无人值守的克隆挂住（见 `AGENTS.md`）。

## 5. 协议对 Unity 宿主的要求

下面由第 1b 节的裁定推出，是 Unity 侧（游玩运行时与 Thart）接入协议时要做到的。「现状」指提交 `bf47c7f` 上的代码。协议从零设计、旧谱面不兼容，所以这些不是修补现有格式的清单，而是接入时的验收条件。依据都标在 rg-protocol 的 ADR 编号上。

几个词先说明：**内容文档**是按协议写成的 JSON；**元素**是其中带稳定 id 的单位；**来源标记**是元素上的 `generated` / `human`；**表现通道**是一组归一化的玩家表现量，例如近期准确率。

1. **读写内容文档时，保留不认识的字段与类型；存回后，文档的规范化形式（RFC 8785）不变。**
   现状：谱面全走 `JsonUtility`，不认识的字段读进来就丢了（`Assets/RhythmDemo/Thart/Core/ThartPackage.cs:83,118`、`Assets/RhythmDemo/Thart/Core/ThartChartIO.cs:80`、`Assets/RhythmDemo/Runtime/ChartData.cs:277`）。
   怎么做由 Unity 侧选，可行的做法有：`Newtonsoft.Json`（`com.unity.nuget.newtonsoft-json`）配 `[JsonExtensionData]` 收下不认识的字段，IL2CPP 下要配 `link.xml`；或者把整份文档当 `JObject` 树持有，只投影出认识的部分；或者把不认识的子树存成原始 JSON 字符串（最容易出错）。（协议 ADR-0002）
2. **时刻用双精度；所有集合按 id 寻址，不按下标。**
   现状：拍与时长用 `float`；`tempos`、`sections`、`cameraKeys`、`paletteKeys` 与多处嵌套的关键帧列表没有 id（`Assets/RhythmDemo/Runtime/ChartData.cs`）。（协议 ADR-0002、0003）
3. **制谱器在元素的值真的变了的时候，把它的来源标记改成 `human`；另记一份「自上次 agent 提交以来被改过的 id」清单，作为附件。**
   现状：只有 `NoteData.protectedNote` 一个类似的布尔值。（协议 ADR-0003）
4. **会对游戏事件起反应的画面由 Unity 实时渲染**：展示元素加三种驱动（时间关键帧、游戏事件反应、表现通道绑定）。只有永远不起反应的画面才能烘焙成视频。
   理由：视频同步容差在播放时是 200–250 ms（`Assets/RhythmDemo/Runtime/VideoBgaRuntime.cs:160`、`Assets/RhythmDemo/Runtime/VisualAuthoringRuntime.cs:444`），比 Good 判定窗（±120 ms，`Assets/RhythmDemo/Runtime/JudgementEngine.cs:22`）还宽。
   现状：`EffectClipData.target` 已经能取 `"judgement"`、按判定档触发（`Assets/RhythmDemo/Runtime/ChartData.cs:185-190`），是这条的雏形。（协议 ADR-0005）
5. **反应的状态只取决于时刻与此前的输入记录**：不读系统时钟，随机数带种子。否则跳转、回放、Thart 的预览都对不上游玩。（协议 ADR-0005）
6. **同一时刻只播一条主视频流**；被触发的片段用序列帧或图集，不用视频。（协议 ADR-0005；`VideoPlayer` 的行为见本仓库 ADR-0001）
7. **会被判定的游戏事件，位置只由时间决定**；反应与表现通道只能改它的外观。（协议 ADR-0005）
8. **媒体不用本机绝对路径引用。**
   现状：Thart 导入场景素材时，把文件对话框返回的绝对路径直接存进 `SceneObjectData.sourcePath`（`Assets/RhythmDemo/ChartEditor/ChartEditorVisualLibraries.cs:497`），游玩时按这个路径读文件（`Assets/RhythmDemo/Runtime/VisualAuthoringRuntime.cs:205,226`），换一台机器就断。协议里媒体怎么寻址尚未裁定（第 4 节）。
9. **每个宿主的 CI 都跑一致性测试**：给定内容文档与输入记录，比对判定与位置。测试集随核心类型一起出。（协议 ADR-0001）
