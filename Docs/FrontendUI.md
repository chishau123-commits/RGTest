# 赛博朋克 UI：标题、歌曲列表、结算与游玩 HUD

全部玩家界面已经作为可交互的 Unity UGUI 接入原来的 `GeometryRhythmDemo` 场景，不是图片或视频。2026-09-18 版本采用深色赛博朋克视觉；现有游玩背景、Note 皮肤、四种判定规则、JSON 格式和不限帧设置保留。

## 1. 如何运行

打开 `Assets/RhythmDemo/Scenes/GeometryRhythmDemo.unity`，等待编译后按 Play。默认先显示黑底启动读条，加载完成后进入标题登录页，而不是立即播放歌曲。也可以运行 `Builds/RhythmHacker/RhythmHacker.exe`；分发时携带整个目录。

### 2026-10-01 编辑器 CanvasGroup 缺失修复

- 上述 Player 验证未覆盖 Unity Editor 的特殊空对象语义。编辑器中，`GetComponent<CanvasGroup>() ?? AddComponent<CanvasGroup>()` 可能保留一个缺少原生组件的包装对象，导致登录/桌面入场访问 `alpha` 时抛出 `MissingComponentException`，中断界面初始化及登录过场。
- 动效中的五处组件获取统一改用 `DesktopMotion.GetOrAdd<T>`，通过 `TryGetComponent` 判断组件存在性；入场组件声明 `RectTransform` / `CanvasGroup` 依赖。入场动画未初始化时不执行 Update，失效引用也不继续写入，保留现有动画、按钮行为和剧情流程。
- 新增编辑器 Play 模式回归 `DesktopMotionEditorValidation.Run`，在隔离项目中运行，不操作用户正在编辑的场景。检查新建/已存在/已销毁组件；通过 EventSystem 射线确认按钮未被透明层拦截，再派发指针按下/抬起/点击，覆盖密码判断、四个应用、任务栏、新闻详情、背景/说明/返回弹窗、进入演奏模式，以及返回标题后重新登录。正常打开工程不会自动运行该验证。
- 执行参数：`-batchmode -projectPath <隔离项目> -executeMethod GeometryRhythm.Editor.DesktopMotionEditorValidation.Run -editorSmokeResult <结果路径>`。不得以独立 Player 回归替代此项编辑器回归。
- 修复后结果：`DESKTOP_EDITOR_SMOKE_PASS=True clicks=37 errors=0`，Windows 构建及 239 项规则检查通过。结果见 `.validation/desktop-editor-reentry/result.txt`、`.validation/desktop-editor-reentry.log`、`.validation/desktop-null-fix-build.log`。

### 2026-10-02 MainUI 音效重设计

- 原创合成 25 个 48 kHz 立体声 PCM 素材：轻触 / 悬停 / 选择，窗口打开 / 关闭 / 最小化 / 恢复，确认 / 取消 / 点赞 / 发送 / 错误，通知，以及保存 / 登录 / 返回标题 / 开始演奏 / 模式就绪 / 关卡开始和六种键盘变化。统一为柔和敲击、短促的玻璃音色和低音量早期反射，避免尖锐长响。
- “开始演奏”专属提示为 1.62 秒：低频起音与上行音符；原有过场完全展开时触发 0.57 秒就绪提示。实际进入曲目另有 0.72 秒提示。登录、返回标题和保存均有独立音色。
- 重要声音在对应动作的实际入口触发，鼠标与 Enter 共用，避免普通点击和重要提示叠播。保存音在保存条件满足后触发；错误密码独立反馈。任务栏区分聚焦、最小化与恢复，开始菜单区分展开和关闭。
- 8 条固定播放通道：4 条普通交互、2 条键盘、1 条关键操作、1 条通知。关键尾音不会被普通点击抢占；悬停 110 ms、键盘 27 ms、普通交互 35 ms 防堆叠，连续通知合并为至少 400 ms 一次。统一输出增益 0.72，素材自身保留动态层次。
- 音频在初始化时预加载，不在按钮按下时生成或读取磁盘。原 BGM 与剧情 / 户外环境音资源未替换。新声音位于 `Resources/Audio/UI`；生成脚本 `Tools/Audio/design_frontend_sounds.py`（Python + NumPy），无外部采样依赖。核心接入 `FrontendUiAudio.cs`、`RhythmFrontendSoundDesign.cs`。
- 试听：`Screenshots/mainui-sound-palette.wav` 按悬停、点击、选中、开 / 关窗、最小化 / 恢复、确认 / 取消、点赞、发送、错误、通知、保存、登录、返回、开始演奏、就绪、关卡开始排列；时间表同名 JSON。`Screenshots/mainui-performance-cue.wav` 为开始演奏单独试听。
- 验证：25 个资源的峰值、DC 偏移、首尾边界通过检查；编辑器实际指针回归 45 次交互、零异常，并验证悬停防叠加与登录 / 开始演奏 / 就绪 / 返回提示次数。命令行 `-frontendSmoke -frontendAudioCapture <目录>` 在真实 AudioListener 录音并检查鼠标 / Enter 防重播和密集输入；追加 `-withFrontendBgm` 验证与现有桌面音乐的混合。
- 最终结果：构建与 239 项规则检查通过；`FRONTEND_AUDIO_PASS=True clips=25 events=88`。单独 UI 录音峰值 -8.49 dBFS，与当前桌面 BGM 叠加峰值 -8.44 dBFS，均无削波。实际录音 / 事件时间线分别位于 `.validation/ui-audio-capture`、`.validation/ui-audio-with-bgm`；编辑器结果 `.validation/ui-audio-editor/result.txt`。试听及实机 WAV 完整解码通过。

## 2. 页面与视觉

以用户提供的 Cytus II 与杂音均衡器截图为视觉方向，使用原创网格／电路边框／信号核心插画，没有复制商业游戏 Logo、角色、封面、字体或 Note 皮肤。

- 启动读条：启动后先进入 2 秒纯黑预载画面，音乐从黑屏第一帧开始播放；随后进入独立 `Boot` 阶段，全黑背景中央显示橙色、黄绿色、蓝色、紫色组成的原创四色信号标志，下方为 `SIGNAL EDITION` 和胶囊式彩色进度条。进度条由 18 个逐格点亮的色块、连续填充和移动光标共同表现，按最短 4.55 秒动画推进，同时等待活动谱面准备；`Kylo - Tell You` 使用 8.5 秒长渐入并从较低输出音量开始，进入标题登录页后继续播放，直到密码验证成功退出登录页才开始淡出。玩家从 MainUI 返回标题时，音乐会重置到 0 秒并从标题页重新渐入。

- 主界面：改为浅紫／粉桌面式大厅，与标题登录页共用同一色板。Diary／Friends／News 三个快捷方式直接放在桌面左侧，不再使用带“快捷方式”标题的白色容器；中央为可最小化、恢复、拖动和关闭的窗口式角色舞台，内部包含状态概览和“开始演奏”入口；原先最右侧的任务管理器已删除，底部动态任务栏与登录页复用浅紫圆角浮动栏，开始与任务按钮均为无描边圆角；任务最小化后底色变浅，底部短色条保留状态提示。三个应用窗口统一使用 Friends 的 `1180×720` 尺寸，并可同时保留在桌面或任务栏中。点击左侧图标后，窗口在目标位置从约 `78%` 尺寸快速放大到全尺寸并同步渐显；从任务栏恢复时，窗口从对应按钮槽位由下往上移动，同时快速放大和渐显；最小化时按相反方向收向自己的任务栏槽位。点击可见窗口对应的任务栏按钮会最小化，点击已最小化任务则恢复。`Resources/Backgrounds/stage-01.png` 至 `stage-03.png` 在中央舞台内按比例裁切，加载成功后自动隐藏占位剪影；资源缺失时才显示空白人物剪影作为回退。
- News：MainUI 左侧“新闻系统”快捷方式进入原创社交流。News 使用与主界面一致的浅紫窗口，标题栏提供最小化和关闭；最小化后可从底部任务栏恢复。首屏每行至少可排列 4 个纵向小窗卡片，显示图片、标题、发布者和正文摘要；初始两条帖子默认是未读状态，MainUI 新闻快捷方式和对应帖子卡片都会显示红点。点击卡片进入详情后，该帖子的红点立即清除，返回预览时不会重新出现。详情窗口显示完整正文、已有评论、标签和爱心点赞按钮，并提供 `< BACK TO FEED` 缩回卡片流。评论保持原有布局，但改为每篇帖子只能提交一次固定的单线路评论，不再提供分支或玩家选择。帖子与基础点赞数集中在 `RhythmFrontendView` 的 `newsPosts` 列表，内容始终留在本地，不接入网络。
- 好友：MainUI 左侧“朋友系统”快捷方式直接展开精简的 Friends 窗口。窗口使用浅紫主题，标题栏提供最小化、好友申请和关闭；最小化后可从底部任务栏恢复。当前只有好友 Tnelis 和接受申请后的 Baka。消息区域占据窗口主体，气泡按文本长度自适应，好友输入时显示闪烁的 `···`。底部是预设台词输入栏与 `SEND` 按钮，不需要先点击输入栏；轮到玩家后，每按一次键盘就推进一帧拼音／汉字合成动画。例如“你好”依次显示 `n → 你 → 你h → 你ha → 你好`。整句显示完后才能按 Enter 或点击 `SEND` 发送。Tnelis 与 Baka 都不再出现选择支，剧情按固定顺序推进并延长了对话轮次。未读好友消息会在 MainUI 好友快捷方式和对应好友卡片同时显示红点；打开聊天后才清除。
- 好友申请：Tnelis 对话结束后关闭 FriendUI 才生成 News03；阅读 News03 并退出详情页才生成 Baka 的 News04，配图为 `baka-post.png`。提交 Baka 帖子的单线路预设评论后，首次回到 MainUI 才会收到带有 `baka.jpg` 头像的好友申请。FriendUI 标题栏右上方有独立的联系人申请图标，带红点时点击打开申请面板；申请面板只允许接受，接受后 Baka 才会加入好友列表并自动打开单线路聊天。
- 日记与旧设备入口：MainUI 左侧“日记本”快捷方式直接打开浅紫悬浮窗口，标题栏提供最小化和返回；最小化后可从底部任务栏恢复。旧的设备主页代码仍保留，包含 `DIARY`、`FRIENDS` 两类入口及图标展开动画，但当前 MainUI 不再依赖它作为必经路径。Diary 始终可查看过去记录；Baka 的对话完成后触发一次线性独白“我想我需要去写点什么。”，为 Diary 快捷方式、旧设备卡片和左侧“新建日记”选项添加红点。该独白只触发一次，没有右侧按钮，按任意键或鼠标左键后关闭。新日记开放后只能写一篇，保存后立即锁定，等待下一次特殊事件。日记左侧所有条目使用统一底色，新日记使用与聊天相同的拼音／汉字逐帧输入，完整后按 Enter 或 `SAVE DIARY` 保存。
- 全局通知：新 News、好友申请和新好友消息会在界面左上方生成通知卡片；多个通知按事件发生顺序从上到下排列。通知使用从左侧滑入、缩放、淡入以及退场淡出动画，可点击快速跳转到对应帖子、好友申请面板或聊天。通知会在 1.5 秒后自动消失，点击卡片或阅读对应内容时也会立即消失；每次新通知播放提高音量后的 `Resources/Audio/notification.wav`。
- 系统弹窗：返回确认、操作说明和背景选择从底部“开始”菜单展开；音乐播放器使用与日记、好友、新闻一致的独立窗口与任务栏入口。弹出层使用浅紫面板、深色正文和紫／粉／青强调色，底下的 MainUI 保持存在，切换时不会重新构建。
- 背景入口：`背景切换` 位于开始菜单，弹出面板中的缩略图显示三张本地舞台；背景图使用前后两层 `RawImage` 交叉渐变，切换完成后才替换当前层，不会出现硬切。
- 音频：启动读条使用 `Resources/Music/Kylo - Tell You.mp3`，以 8.5 秒淡入并持续经过标题登录页，直到密码正确退出登录页才在 1.2 秒内淡出；实际输出目标音量为 `0.17`，约为此前的一半。密码正确后播放一段约 1.35 秒的运行时合成电子开机和弦，由低频扫频、根音／五度和八度泛音组成，并使用软限幅和高输出增益进一步放大，音效源音量设为 `20`，不再使用旧的机械提示音。标题在 3 秒内淡出；随后 MainUI 在 1.8 秒内浮现，`Resources/Music/main bgm` 的默认初始音量保持 50%，最终输出再乘 `0.64` 作为全局衰减，因此同样百分比下实际 BGM 更小。按下 `ENTER!` 后 MainUI BGM 淡出，模式层加载 `Resources/Music/暴力四叶草 - 『未许之地』活动剧情BGM2.mp3`；从 0 秒播放并用于模式选择、剧情关卡和自由选曲界面，输出目标音量为 `0.08`。开始游玩时模式音乐淡出，返回模式层时恢复。普通 UI 图标点击音整体降低；好友逐字输入时，每个合成帧随机播放一次键盘敲击音，音色由短噪声瞬态、低频木质共振和十二个随机变体组成。
- 模式选择：分为 `STORY MODE` 与 `FREE MODE` 两张大型路线卡片。剧情路线显示 MainUI 同步的当前 `0-1` 进度和后续锁定节点；自由模式显示“可游玩全部谱面”的路线提示。
- 剧情章节：横向展示 `0-1`、`0-2`、`0-3` 三个章节节点，当前进度高亮，后续节点锁定。`0-1` 已接入 `Resources/Story/main-story.json`，点击当前章节卡片进入剧情播放。
- 剧情播放：沿用 MainUI 的深色叠层、切角面板、青色强调轨和 Mono 标头；使用全屏背景、透明角色立绘、底部对白面板和章节选择返回入口。选项仅设置变量，后续对白按变量替换文本。进入关卡步骤复用正式谱面播放，结算后由“RETURN TO STORY”回到剧情。
- 自由选曲：左侧滚动曲库，中间独立封面套，右侧曲名／作者及 BPM、时长、音符数、路径数仪表。底部区分手动开始与自动预览。
- 结算：大号总分区、独立荧光黄评级、青色准确率、四色判定统计卡片与再次游玩入口。
- 加载、缺失资源错误、空曲库：同一套边框、字体和状态语言，不加入虚假的百分比、网络状态或不可玩的曲目。
- 游玩 HUD：深色顶部仪表、荧光黄 Combo、青色准确率与进度条、底部模式／声音／重开控制。中间仍是原有三维舞台，没有加全屏滤镜或修改 Note。
- 暂停：半透明遮罩和切角控制台，保留恢复／返回选曲功能。遮罩只在暂停时接收点击；装饰网格、边框、文案不拦截游玩触点。

界面框架文案沿用 Demo 的英文风格；剧情对白、News 正文／评论、Friends 聊天和好友申请全部使用中文，并切换为运行时中文字体回退。角色名保留英文原文，例如 Tnelis 与 Baka。字体为随工程打包的 **Rajdhani Bold / Medium** 与 **Share Tech Mono**，均为 SIL OFL 1.1 开源字体，不依赖电脑安装。字体位于 `Resources/Fonts`，同目录保留完整许可证；分发包另附 `Docs/ThirdParty`。

菜单没有大面积 Bloom 或模糊后处理。所有页面切换统一由最上层全屏黑幕控制，因此 MainUI 的背景和 UI 始终同步淡入，切换时也不会短暂露出旧页面。标题账户头像使用 `Resources/UI/LoginAvatar.jpg` 的本地 `RawImage`，不接入视频时钟；资源缺失时 `CyberTitleGraphic` 和 `R/H` 头像继续提供完整登录背景回退。MainUI 使用 `RawImage` 展示 `Resources/Backgrounds/stage-01` 至 `stage-03` 的图片，并按画布比例做居中裁切。普通页面入场淡入为 0.18 秒，标题进入和离开均为 3 秒，MainUI 进入为 1.8 秒。

MainUI 的 `ENTER!` 使用分片幕布合拢、像素读条、第二层幕布展开的旧版模板进入模式选择；前两层幕布共用 `0.90` 秒，像素读条使用 `2.10` 秒，因此音乐开始后的第 `3.0` 秒读条恰好完成。从模式选择返回时仍使用信号收缩／展开转场。转场完成后才销毁旧页面，不会把两个页面叠成静态弹窗。

共享主题在 `CyberTheme.cs`：深底 `Background`、分层面板 `Panel/PanelLight`，强调色 `Cyan/Purple/Lime/Pink`。优先从这里调整颜色与字体。布局数字集中在 `RhythmFrontendView`，游玩读数集中在 `DemoHud`；不要为了修改 UI 去改 `SceneVisuals` 或判定引擎。

布局采用 1600×900 设计尺寸，在实际 Canvas 的安全区域内等比容纳。它不是渲染分辨率：独立程序默认 1920×1080，Game 视图也可选 Full HD。非 16:9 窗口仍保持主要控件完整，不通过裁掉两侧内容强行铺满。

## 3. 改游戏名字

游戏标题为 **Rhythm Hacker**，默认两行 `RHYTHM`、`HACKER`。`RhythmDemoController` 的 **Game Title** 可在非 Play 状态修改；页眉品牌名自动合并为一行，品牌标记统一使用 `R/H`。

Windows 产品名由 `ProjectSettings.productName` 和批处理构建入口 `DemoBuildTools.ValidateAndBuild` 统一设置为 `Rhythm Hacker`，构建输出为 `Builds/RhythmHacker/RhythmHacker.exe`。

`RhythmDemoController.Show Frontend` 默认开启。开发时关闭可跳过菜单直达旧的游玩 Demo；`-demoSmoke` 始终跳过菜单，用于原有玩法验证。

## 4. 新增歌曲与 JSON 约定

歌曲列表扫描 `Assets/RhythmDemo/Resources/Charts/` 中的 TextAsset JSON。每一份合法谱面就是一个可选条目，不另造与谱面不一致的假数据。当前只有真实可玩的 `Geometry / First Light`，没有虚构的其他歌曲或难度。

1. 把制谱器导出的有效 JSON 放到上述目录，文件名保持唯一。
2. 使用谱面已有的 `title`、`author` 元数据。标题含 ` / ` 时，详情主标题取最后一段，完整名称仍保留在数据中。
3. 配置 `audioResource` 指向 Resources 下的音频，不带扩展名；为空仍使用原有合成演示音乐。
4. 重新启动场景／重新构建，即可收录。运行中的列表不会监听磁盘热更新。

BPM 范围、时长、Note 数、同时路径上限均从 JSON 计算。无效 JSON 会跳过并在 Console 发出 Warning；若某个有效谱面引用了缺失音频，启动时给出可读错误并允许返回选曲。空列表也有空状态，不提供不能使用的 Play 按钮。

`Chart Override` 和 `-demoChart <path>` 保留，显式指定的谱面排在首位。添加新曲时不需要修改选曲 UI、计分逻辑或 JSON schema。不同难度当前表现为不同 JSON 条目，尚未引入“歌曲—多个难度”的目录层级。

## 5. 结算的真实性

`PlayResult` 在结束时从 `JudgementEngine` 复制成绩，之后重试不会把已显示的结果改成零。显示的是本次真实判定数据，不是固定的满分样例。

- 自动演示显示 `AUTOPLAY / PREVIEW` 与“不是玩家记录”的提示。
- 用左右方向键跳转后显示 `PRACTICE SESSION`，分母使用练习区间可判定 Note 数。
- 手动全曲显示 `MANUAL PLAY`。
- 目前不写入历史成绩、最高分、排行榜或云端记录，界面明确说明尚未开启保存。
- 歌曲结束会统一处理尚未判定的末尾音符，避免谱面时间被夹到歌曲总时长后留下 Pending。

评级是当前 Demo 的展示规则：100% 为 SSS，≥99% 为 SS，≥98% 为 S，≥95% 为 A，≥90% 为 B，≥80% 为 C，其余为 D。评级不改变原有计分算法。
