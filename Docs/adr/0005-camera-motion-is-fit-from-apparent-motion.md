# 运镜由视频的表观运动生成，不是恢复真实相机

Status: accepted

三维玩法段的**运镜**从视频里量测出的**表观运动**（整层缩放 / 旋转 / 平移）**生成**：先自动出草稿写进谱面，再由谱师手工修。**不去恢复真实相机**。

## 为什么

- **单目视频里"变焦"与"推拉"在投影上不可分辨**，两者在残差上等价，而相机模型里也没有任何字段记录"这是变焦还是位移"（见 [CameraModelCapabilities.md](../Docs/CameraModelCapabilities.md) §4.4）。所以"恢复"本身不是一个良定的问题——不是一个难问题，是没有唯一解的问题。
- **本条素材的实测倾向是分层二维动效**：帧间运动**不是**单一平面单应（`resid_H/flow = 0.430`，两条已知 3D 对照是 0.055 / 0.085），但也**没有**随深度变化的视差证据。这类画面里未必存在一个真实相机。
- **纯手工逐镜头敲相机键不可接受**：goodtek60 有 **48 次硬切**（中位镜头 0.97 s）。
- **纯自动不可修也不可接受**：拟合出来的东西没有唯一正确答案，而"毫无违和感"本质是主观判断。

## 映射规则（本决定的一部分）

| 量测到的表观量 | 写进哪个自由度 | 硬限制 |
|---|---|---|
| 整层缩放 `s` | `distance`（推拉） | **下限 12**（`ChartData.cs:343-345`），可用幅度有限 |
| 整层旋转 `θ` | `roll` | 完整 360° 可用 |
| 整层平移 `dx` | `orbit`（偏航） | **只能小角度**——大角度 yaw/pitch 会让 3D 前景与平面视频的透视分家（`ChartEditorCameraPoseVerification.md:85`） |
| 整层平移 `dy` | `height` | 无上下界校验 |
| 变焦 | **不写**（`fov` 固定） | fov 变化在远平面视频上**看不出来**，只会让前景与视频分家 |
| 镜头硬切 | **不写**（交给视频自身的硬切） | 相机是同一个 `Camera` 上的连续函数，且相邻键 `beat` 必须严格递增 |

键**按镜头给**（与硬切对齐，段内插值），不逐秒——否则会在镜头内部产生与画面无关的运镜。

## 后果

- **运镜不能用"与视频逐帧对齐"来验收**——它本来就不是恢复出来的。
- 这与既有的"验收要可机器检验"要求产生张力。可机检的部分是：**管线**（量测输出稳定、生成的键落在相机模型的合法范围内、同输入可复现）与**代理指标**（把运镜施加到 3D 前景后，前景的表观运动与视频表观运动在幅度与相关上达标）；**观感仍由谱师确认**。
- **Thart 必须能编相机键**（"手工修"的落脚点）——它今天只有一个写死的键（`Assets/RhythmDemo/Thart/Desktop/ThartEditorController.cs:990`）。
- **运镜只属于三维玩法段**：二维玩法段的判定是 `Camera.WorldToScreenPoint` 的函数，相机一动判定域就跟着动（见 [CameraModelCapabilities.md](../Docs/CameraModelCapabilities.md) §3）。
- **若谱面带 `videoSpace`，`cameraKeys` 会被整体绕过，且 `cameraMotionClips` 在游玩时不执行**（`SpatialDirector.cs:260`、`RhythmDemoController.cs:325`）→ 运镜将无处安放。三维段落的谱面不得启用 `videoSpace`。
- 视频贴在相机远平面时，**任何相机参数都不影响视频本身**；运镜只能让 3D 前景**呼应**视频的表观运动（另见第七轮 Q5）。

## 落地形态（已定）

- **写进 `cameraMotionClips`**，不是 `cameraKeys`：它是**加性**的（`VisualAuthoringRuntime.cs:44-46` 在已算好的位姿上叠加位置/旋转/FOV），天然表达"在一个稳定基准姿态上叠加逐镜头运动"；它已有的 `keys`（归一化时间 → 位置/旋转/FOV）正好容纳逐帧提出的曲线；而且它**不改基点**——二维玩法段只要不放 clip 就等于相机固定，两套玩法规则一致。
- **视频的承载按段分**：二维玩法段保持远平面全屏（铺满画面 + 音符叠上）；三维玩法段把视频放到**世界空间的一块板**上，这样相机运动才作用得到它、透视才与前景一致。代价是世界空间板需要"板外兜底"设计（转头或推近会看到板的边界之外）。
- **验收 = 管线可复现 + 代理指标 + 谱师确认**：
  - **管线**：量测输出稳定、生成的键落在相机模型合法范围内（`distance ≥ 12`、`fov ∈ [30,85]`、`beat` 严格递增）、同输入可复现。
  - **代理指标**：把生成的运镜施加到相机上，渲染一组**固定的标定探针**（若干固定的世界空间标记）并量测其表观运动，与视频的表观运动比较幅度与相关性。用**固定探针**而不是 3D 前景，是为了让指标只反映相机、不被谱面内容（音符排布）污染；并且**复用与视频量测同一套估计器**，让"输入信号"与"输出校验"处在同一坐标系。
  - **观感**仍由谱师确认——这是唯一无法机检的部分，也是"毫无违和感"的最终判据。

## 考虑过的替代

- **恢复真实相机**（SfM/SLAM 那一类）：单目不可分辨变焦与推拉，且本条素材是分层二维动效——不是良定问题，被否。
- **纯手工编运镜**：48 次硬切，工作量不可接受。
- **纯自动、不可修改**：没有唯一正确答案，且"毫无违和感"是主观判断，被否。
