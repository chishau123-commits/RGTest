# 玩法与呈现跟随 BGA 素材的维度，两套玩法并存

Status: accepted

一条 BGA 的**素材维度**决定用哪套玩法与哪种呈现：平面素材配**二维玩法**与平面呈现，立体素材配**三维玩法**与三维呈现（即现状那套，保留不动）。判据落在**呈现**——平面素材配了光照三维网格就是"违和"。因此游玩运行时**并存两套玩法**，而不是用一套替换另一套。

## 为什么

- 现状的违和感有明确来源：`BV12K4y1P7ps`（EBIMAYO - GOODTEK）的 BGA **两种维度都有**，而运行时把整条都当三维世界来呈现（世界空间 Note、雾、平行光、相机骑路线）。
  **这条 BGA 里的真实 3D 段落**（复核结论，见 [BgaDimensionalityRecheck.md](../Docs/BgaDimensionalityRecheck.md)）：**91–105 s** 挤出立体的 GOODTEK 字样在空间中飞行、多轴旋转、逐面前缩，配紫色圆盘与线框球（把握很高）；**54–56.5 s** 白/黄/青线框笼旋转，有真实顶点与内外连杆（中高）；**63.5–67 s** 青绿肋状锥体沿视线透视前缩（中）。其余约 105 秒是平面矢量动效（含大量"伪三维"装饰：透视网格、放射星芒、多层视差）。
- **更正（重要）**：第一轮量测曾判"整条都是平面图形动画"，**那个结论是错的**。错在判据：单应变换平面性检验问的是"一个全局平面模型能否解释画面运动"，它对**"3D 小物体 + 无纹理深背景"天然失效**——同一个 3D 镜头内部 `H/flow` 在 0.216–0.746 之间摆动，一个都没识别成 3D。另外本轮验证发现这些 3D 是**平面着色**的（侧壁竖直扫描 40 像素恒为同一灰阶），所以"连续明暗渐变"这类判据在本素材上同样无效，反而会在片尾卡与 WARNING 画面上误触发。**真正定案的是几何（透视前缩 + 背面自遮挡）加上人眼看画面。**这正是本 ADR 采用"内容判据 + 谱师逐段确认"的经验依据。
- 三维那套**有现成的用武之地**，不是死代码：仓库里已有真正的 3D BGA 素材链——`.buildtmp/bga20/video.mp4`（Blender 连续渲染 "Firefly the Summer"，20s / 60fps / 1920×1080 / 0 次硬切）与其源文件 `Firefly_the_Summer_Opening_v03.blend`、`scene.glb`。删掉三维玩法等于把这条通路一起废掉，且不可逆。
- 参照的 Groove Coaster 官方机制证明"平面素材 + 伪三维呈现"也能成立（其判定是一维的 avatar 压 target），但那是**另一条路**；本项目的目标是"完全融入视频"，所以选了"呈现必须与素材同族"。

## 后果

- [CONTEXT.md](../CONTEXT.md) 新增 素材维度 / 玩法维度 / 呈现维度 / 维度规则 / 三维玩法 / 二维玩法 / 判定域 / 判定域 Note 等词条；**世界空间 Note** 与 **判定平面** 被限定为"只在三维玩法里存在"。
- [VideoBgaBranchingPlan.md](../VideoBgaBranchingPlan.md) 里三处条文被本决定取代：非目标的"不把 Note 改成 2D 屏幕空间"、决定 12"Note 保留 3D 世界空间位姿"、结尾重申的"不把 Note 2D 化"。它们**在三维玩法里仍然成立**，但不再是全局约束。
- 二维玩法需要 Note 的位置信息，而 `NoteData`（`Assets/RhythmDemo/Runtime/ChartData.cs:145-152`）现在**零坐标字段**。形态定为自由二维坐标，见 [ADR-0004](0004-2d-mode-uses-free-2d-coordinates.md)。
- 素材维度由**打包/导入时量测**得到，写进 `.thr`，并且**谱师可以覆盖**——量测有盲区（分不清"真 3D"与"2D 多层视差滚动"，纯旋转的 3D 场景会误判为平面），不能全自动。运行时不在开播前做量测。粒度是**逐段**，不是逐曲。
- **换维**：维度逐段确定，所以一首歌里可以在**玩法段**边界同时切换玩法与呈现。视频的硬切统计（goodtek60 为 48 次 / 124.1 s、中位镜头 0.97 s、25 个镜头短于 1 s）意味着段必须**归并**——按镜头粒度换玩法等于每 1 秒换一次操作模型，不可玩。最小段长另定。
- 三维玩法保持现状：`SpatialDirector` / `StageSpline` / `StageVisuals` / 雾与光照**都不删**。
- 判定面与呈现的既有验收（含 `-demoBgaSmoke` 的 24 项）是在三维玩法宿主上跑的；二维玩法建起来之后要在它自己的舞台上重跑。
- 视频与音符的空间关系定为**全屏底图 + 音符叠上去**（不采用 BMS 传统的"BGA 专用区域"，因为专用窗口自带可见边界，与"毫无违和感"不相容）。

## 考虑过的替代

- **全盘二维化、删掉三维玩法**：被否。三维 BGA 素材已经存在，删掉不可逆。
- **以玩法为权威、素材只是背景**（Groove Coaster 的实际做法）：被否。这正是当前违和感的来源。
- **素材为权威，但玩法与呈现都必须同族**（判据不指定）：被否——用户选了"判据落在呈现"，因为违和感是呈现层的事，而把玩法几何绑死在素材上会连"平面素材 + 一维玩法"这类成熟做法一起禁掉。
- **同一首歌内分段换维度**：**已采纳**（用户裁断；原先否决见下）。原否决是基于"维度 = 有没有真实相机视差"这个判据，而该判据对这条 BGA 给出"整条平面"——**复核证明那个结论是错的**：91–105 s 等段落有真实三维几何（透视前缩 + 背面自遮挡）。用户的判据是**画面里有没有三维造型与透视**，按后者这条 BGA 两种都有。判据换成内容判据后，"分段换维度"不再是噪声而是设计需求。
